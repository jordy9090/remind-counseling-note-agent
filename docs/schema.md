# 스키마 정의 (Schema Specification)

## 1. StructuredCase (구조화된 케이스)

LLM이 입력 정보를 구조화한 결과. 모든 문서의 기본이 되는 중간 표현.

| 필드 | 설명 | 예시 |
|------|------|------|
| `basic_info` | 케이스 기본 정보: ID, 회기번호, 내담자 특성, 상담 영역 | "케이스ID: CASE001 \| 회기: 3 \| 김지은(여, 대학생)" |
| `presenting_problem` | 내담자의 주 호소 및 당면 문제 | "졸업 앞두고 취업 불안, 진로 선택 어려움" |
| `goals` | 이 회기의 상담 목표 | "강점을 바탕으로 진로 옵션 검토 및 행동 계획 수립" |
| `session_content` | 상담 중 실제 진행된 과정과 내용 | "강점 점검 → 진로 옵션 탐색 → 행동 계획 수립" |
| `counselor_intervention` | 상담사의 개입 방식, 기법, 소견 | "강점 중심 상담으로 자신감 강화, 구체적 행동 계획 수립" |
| `client_response` | 내담자의 반응, 변화, 감정 | "불안감 감소, 진로 확신 증가, 행동 계획 동의" |
| `assessment` | 상담사의 전문적 평가 | "내담자는 충분한 강점 보유, 자신감 회복 추세" |
| `next_plan` | 다음 회기 또는 추후 계획 | "인턴십 지원 → 다음 회기 진행 상황 점검" |

## 2. SessionSummary (회기 요약)

StructuredCase를 바탕으로 한 전문가 수준의 회기 요약.

| 필드 | 설명 | 길이 |
|------|------|------|
| `session_content` | 이번 회기에서 다룬 주요 상담 내용 | 2-3문장 |
| `counselor_opinion` | 상담자의 전문적 소견 및 평가 | 2-3문장 |
| `session_summary` | 회기 전체의 요약 (클라이언트에게 피드백할 수준) | 2-3문장 |
| `next_counseling_plan` | 다음 회기를 위한 상담 방향 및 계획 | 2-3문장 |

## 3. VerificationReport (검증 리포트)

생성된 정보의 신뢰성을 4가지 카테고리로 분류.

### 카테고리

1. **grounded** (초록색)
   - 입력에 명확하게 근거한 항목
   - 축어록이나 상담사 메모에서 직접 확인 가능

2. **ungrounded** (주황색)
   - 근거가 약하거나 추측/해석이 포함된 항목
   - LLM이 상식이나 일반화로 생성한 부분

3. **sensitive** (빨강색)
   - 민감한 개인정보나 위험 신호
   - 정신건강, 가족 문제, 신분 정보 등
   - 별도의 보안 및 윤리 검토 필요

4. **needs_human_judgment** (파랑색)
   - 상담사의 직접 판단이 필요한 부분
   - LLM이 결정하기 어려운 전문적 평가
   - 예: 실제 효과성, 예측 가능성 등

### VerificationItem 구조

```typescript
{
  "content": "검증 항목의 내용",
  "source": "어디서 나온 정보인지 (예: '입력', '생성됨', '검증')"
}
```

## 참고: TypeScript 타입 정의

모든 필드는 `string`으로 정의되며, 비어있을 수 있습니다.
VerificationReport의 리스트 필드는 `VerificationItem[]` 형태입니다.
