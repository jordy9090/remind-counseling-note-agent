Two older architecture/setup statements also conflict with current source: authenticated storage requires the public key and verified user JWT, so the deployment document's service-role-key requirement is not a requirement for that path; generated-note persistence does call transcript evidence ingestion, despite the architecture document's older statement that it does not. ## Independent code changes

- Unexpected signature/archive validation failures now release uploaded temporary files, including cancellation and malformed UTF-8 ZIP names. Successful uploads still transfer cleanup responsibility to their consumer. Process termination and operating-system unlink failure remain separate limits.
- Dense confirmed-note memory is admitted only when its owned current confirmed field agrees. Cleared confirmed recency summaries do not recover old draft text. Recomposition caches include a complete owned note-source fingerprint, reject stale or unavailable snapshots, and retain ordinary reuse when sources are unchanged. The fingerprint has an explicit 500-note/12-page work bound; exceeding it fails closed instead of silently accepting incomplete coverage. This changes admission of confirmed-note content, not physical index deletion, vector provenance or every evidence/KB cache boundary.
- The [offline retention planner](retention-planning.md) accepts explicit approved policy/trigger/basis/version and verified metadata. It separates preservation, operational deletion thresholds, holds and local/provider/backup status. Unknown or conflicting evidence blocks eligibility. It has no active deletion executor, endpoint, scheduler or default duration; output is planning evidence only.
