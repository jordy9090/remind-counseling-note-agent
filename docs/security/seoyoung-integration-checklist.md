## Review setup

1. Record feature PR, exact SHA, base SHA and changed paths. Compare against independent security PRs; mark overlapping implementation files **yes/no/unknown** and identify merge order. For overlapping production modules, report the failing interface/test and coordinate a patch instead of implementing the feature twice.
2. Use synthetic counselors A/B, separate browser contexts and uniquely identified cases/sessions/drafts. Use markers such as `SYNTHETIC_RAW_A`, `SYNTHETIC_MASKED_A`, `SYNTHETIC_PRIVATE_REFLECTION_A`, `SYNTHETIC_THIRD_PARTY_B` and addresses ending in `.invalid`. They must not derive from real people or interviews.
3. Stub LLM/STT/embedding calls and record only synthetic requests in the test harness. Run against isolated local resources first. Mocked PostgREST/JWT tests do not verify hosted RLS, deployment configuration or provider contracts. Any remote DB/RLS change, real-data access, retention-policy change, Production deployment or main merge requires approval.
4. Include direct authenticated-account replacement events and late responses from the previous account, as well as ordinary logout/login. For masking, exercise edited confirmed notes reused through every prior-session retrieval fallback, in addition to newly entered material. Keep private failure reproductions outside this public repository until coordinated remediation.

## Execution and reporting

Run focused tests for the reviewed interface, then affected regression checks. Use one browser integration checkpoint for guest → login → save → reload plus A/B negatives against the exact candidate. Reuse passing results when relevant code/configuration is unchanged; do not recreate accounts or repeat the whole workflow for documentation-only changes. Use compatible dependency versions and record the environment with any failure so a harness mismatch is not attributed to product behavior.

For each executed row record: feature SHA and security-test SHA, environment/deployment URL if any, exact command, synthetic run ID, expected/actual result, whether network/storage was mocked, remaining gap, and cleanup result. Link evidence in [implementation-progress.md](implementation-progress.md). Clean up created synthetic rows/accounts/files once and verify the result; local mocks create no remote cleanup obligation.

Public-source safety: keep all fixtures synthetic and publish only generic findings and aggregate results. Do not copy private source text, interview details, credentials, real counseling content, provider response bodies, or sensitive policy-reproduction payloads into tests, logs or PRs. Retain such review details privately with the owner. Integration approval must remain separate from merge, Production, remote-policy and retention approvals.
